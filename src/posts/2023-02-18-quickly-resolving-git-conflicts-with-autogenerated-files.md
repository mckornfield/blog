### Generated file merge conflicts, so silly

There are plenty of languages that have files that are essentially “autogenerated” based on some core infrastructure files.

For example, in Golang, there is a go.mod and a go.sum file that are basically generated based on what packages you install with `go get` . However, if you happen to edit these files (or some downstream files, like the ones generated by [gazelle](https://github.com/bazelbuild/bazel-gazelle)) and run into merge conflicts, solving them can be quite annoying.

Don’t worry, there’s a simpler path that resolving these conflicts

### The Steps

1. `git fetch origin main && git rebase origin/main` assuming you’re tracking a branch called `main`
2. `git checkout --ours go.sum go.mod` and any other autogenerated files
3. Re-add any dependencies you wanted for your branch by hand, i.e. rerun the `go get` commands you had
4. Rerun any commands necessary to generate autogenerated files
5. `git add -u && git rebase --continue` to finish the rebase

All in one this might look like:

```go
git fetch origin main && git rebase origin/main
git checkout --ours go.sum go.mod
# Example dependency
go get go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc
bazel run //:generate_files
git add -u && git rebase --continue
```

### The Explanation

The main thing you might not have used that is part of the trick is `git checkout --ours` . In this case, where we’re rebasing, `ours` refers to the base/main branch, and `theirs` refers to the branch you’re trying to rebase (this is the opposite of what you might intuit, but you have to think of it from git’s perspective of starting on the main branch and applying your commits).

By doing this checkout, you are essentially undoing your changes and putting yourself in the state that the main branch is in.

Then you add back in the dependencies, either manually or using a command in the case of Go, so that you can avoid dealing with silly merge conflicts.

Hopefully this saves you a bit of time, thanks for reading!
