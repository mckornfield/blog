### What is a “Kubernetes client?”

If you’re reading this you probably know what a client is… but it’s good to be clear since things might get complicated quickly. A client is someone or something that is accessing a remote server, even if that server is running on the same machine.

All communication within Kubernetes is server based, in the sense that the `kubectl` or our friend the [Kubernetes Python Client](https://github.com/kubernetes-client/python) all issue commands to the `kube-apiserver` , an [OpenAPI based RESTful server](https://kubernetes.io/docs/concepts/overview/kubernetes-api/) that lets us do everything from query what’s running to executing commands on `Pods` running within the system.

(OpenAPI -> standard for defining the inputs and outputs of a system that templates can be built around.

RESTful -> GETs, POSTs, the types of requests that browsers love)

When you use `kubectl` or `import kubernetes` into a Python script, you’re sending and receiving responses to that kube-apiserver, which talks to other components behind the scenes within the control plane in order to perform CRUD on existing resources, or return information about existing resources and their states.

### Installing the Python Kubernetes Client

If you’re just going for it:

`pip install kubernetes`

But if you want something more rigorous consider at least using a pinned version in a `requirements.txt` file:

```ini
kubernetes==12.0.1
```

And then with a `pip install -r requirements.txt` you have *almost* everything you need to get started.

Of course… we’re missing a Kubernetes cluster! Here are a few ways to get started with one

- Use a cloud provider, like [GCP](https://cloud.google.com/kubernetes-engine/docs/deploy-app-cluster) or [AWS](https://docs.aws.amazon.com/eks/latest/userguide/getting-started-eksctl.html) to spin up a cluster and get your `kubeconfig` set up to talk to them
- Just do it with [minikube](https://minikube.sigs.k8s.io/docs/start/)!

### Authenticating with the client

There are really two paths to walk down once you have the Kubernetes client installed, from within the cluster or via a kubeconfig.

```python
from kubernetes import config

# From a pod within the cluster
config.load_incluster_config()

# From a machine with a defined kubeconfig file
config.load_kube_config()

# or a dictionary
with open('my_kubeconfig.json') as f:
  kubeconfig = json.load(f)
  config.load_kube_config_from_dictionary(kubeconfig)
```

Once you’ve chosen your adventure, every call *afterward* to one of the relevant APIs will be authenticated, assuming you have a ServiceAccount and Roles properly defined if you’re in the cluster, or assuming you have the proper access to the client if you’re using a kubeconfig.

### OK… now how do I use it?

The client is very… autogenerated… from the OpenAPI spec. Creating some of the classes can be quite daunting. For example, this is what creating a `Role` and a `RoleBinding` might look like:

```python
from kubernetes import client, config

config.load_incluster_config()
policy_api = client.RbacAuthorizationV1Api() # API used to create roles

role = client.V1Role(
    metadata=client.V1ObjectMeta(name="my-role"),
    rules=[client.V1PolicyRule([""], resources=["pods"], verbs=["get", "list"])],
)
policy_api.create_namespaced_role(namespace="my-namespace", body=role)

role_binding = client.V1RoleBinding(
    metadata=client.V1ObjectMeta(namespace="my-namespace", 
                                 name="my-role-binding"),
    subjects=[
        client.V1Subject(
            name="user", kind="User", api_group="rbac.authorization.k8s.io"
        )
    ],
    role_ref=client.V1RoleRef(
        api_group="rbac.authorization.k8s.io", kind="Role", name="user-role"
    ),
)
policy_api.create_namespaced_role_binding(namespace="my-namespace", 
                                          body=role_binding)
```

Where every piece of the `Role` maps to something defined in this OpenAPI spec. See the [Role](https://github.com/kubernetes-client/python/blob/master/kubernetes/docs/V1Role.md) page for an example. This simply gives a user named “user” the ability to get and list pods in the `my-namespace` namespace.

Or you can look at this [snippet from a while back](https://github.com/Greenstand/treetracker-infrastructure/blob/master/tag_lister/list_tags_for_deployments.py), where I listed all deployments in all namespaces in a cluster

```python
from kubernetes import client, config

def main():
    try:
        config.load_kube_config()
    except:
        # load_kube_config throws if there is no config, but does not document what it throws, so I can't rely on any particular type here
        config.load_incluster_config()

    v1 = client.AppsV1Api()
    ret = v1.list_deployment_for_all_namespaces()

    # Do some printing with `ret`
```

Needless to say `ret.items` is a pretty large list of things, even with only a few deployments it still contains all the containers, etc. info.

If you get stuck on how to use the API, look for snippets online or work backwards from querying objects created via regular manifests, using the `get_namespaced_...` functions. Fortunately printing them puts them in a format you can just paste back in as python code :)
