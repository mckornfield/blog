We’ve joked about this at work a bit so I thought it would be funny to write out a clue board for production software outages.

*There’s been a production outage and all you have are log files and angry customer tickets to narrow down the suspects. Here are the suspects:*

### Suspects

1. The DevOps Engineer
2. The Software Intern
3. The Security Engineer
4. The Senior Architect
5. The New Guy
6. Brett

### Mechanism (Weapon)

*Now that you’ve met the suspects, here are the mechanisms they had available to cause the outage:*

1. Deleted
2. Rebooted
3. Stopped
4. Encrypted
5. Released a Bug to
6. Tripped Over the Power Cable Leading to

### Targeted System (Room)

*Now that we have our causes, we just need our targets, which might include:*

1. The Database
2. The Kubernetes Cluster
3. The Load Balancer
4. The Prototype that Made it to Production
5. The Redis Cluster
6. The ElasticSearch Cluster
7. The Application Server
8. The DNS Server
9. The Datacenter
10. The Mainframe (haha)

### Trying it out

Now you can try them out, just get a dice roller handy…

I rolled 5,5,9, i.e.

**The New Guy Released a Bug to the Datacenter.**

Ah new guy, when will you learn.

Or how about 1,2,1

**The Security Engineer Rebooted the Database.**

Gotta patch those databases!

Lastly 3,6,5

**The DevOps Engineer Tripped Over the Power Cable Leading to the Redis Cluster.**

Someone should really work on the cable management there…
