## Who cares about licenses?

Businesses.

Software licenses that are non-permissive are super dangerous to a business, either meaning they need to Open Source their private offerings (AGPL), or should be paying Oracle or the like big money (Commercial License).

MySQL has [one](https://www.mysql.com/about/legal/licensing/oem/) that is essentially both: either your software must be FOSS or you have to pay.

So if you’re just randomly adding Go Packages to your businesses’s software that you intend to ship, it’s worth your due diligence to make sure you don’t have any non-permissive licenses.

## What tools are out there for Go?

There’s more exhaustive lists than one I can put together, [for example here](https://seankhliao.com/blog/12021-04-13-go-license-scanning/). The short list I went through was:

- [go-licenses](https://github.com/google/go-licenses)
- [go-mod-licenses](https://pkg.go.dev/github.com/Bobgy/go-mod-licenses)
- [This weird directory for kubeflow](https://github.com/kubeflow/testing/tree/master/py/kubeflow/testing/go-license-tools)

I’ll say that like the other blog author mentioned, I think go-licenses is the way to go, but it’s not perfect, and the output format is either CSV or a go template, which is always fun to work with.

I’ll run through the template I used to generate my output, the rough edges around using the tool, and what you can do if it misses any licenses.

### Go template for a License JSON

If you want an output format that’s not a simple CSV, you can use a template. Go templates are weird, so here’s one written to create a JSON file that I can walk you through.

For instructions on what the template can use, see here: <https://github.com/google/go-licenses#reports-with-custom-templates>

To install `go-license`, `go install github.com/google/go-licenses@latest`

The contents of `template.tpl` will be:

```bash
{
{{- $first := true}}
{{- range . }}
    {{- if $first -}}
        {{- $first = false -}}
        {{- printf "\n" -}}
    {{- else -}}
        {{- printf ",\n" -}}
    {{- end -}}
{{- printf "    " -}}"{{ .Name }}:{{ .Version }}" : "{{ .LicenseName }}"
{{- end }}
}
```

1. This takes the range of output, and for the first item, simply adds a newline in front, but for all other input adds a comma and then a newline
2. Each line has 4 spaces in front of it, and then the “package:version” (e.g. as a key, with the “license name” (e.g. Apache-2.0) as the value
3. All of the dashes you see (though some might be unnecessary) help to remove the whitespace generated by the templating conditions.

Before running the finder, you’ll also need to download the licenses. I tested this out on this trending [casbin](https://github.com/casbin/casbin) repository.

```go
go mod download
go-licenses report ./... --template licenses.tpl > licenses.json
```

This will write the standard output of the command to a `licenses.json` file, and the standard error to the console.

Running this in the repository I got a pretty small file. Note the version for the repo itself is “unknown”.

```json
{
    "github.com/Knetic/govaluate:v3.0.1-0.20171022003610-9aa49832a739" : "MIT",
    "github.com/casbin/casbin/v2:Unknown" : "Apache-2.0",
    "github.com/golang/mock/gomock:v1.4.4" : "Apache-2.0"
}
```

### Rough edges for go-licenses

The biggest rough edge is that the tool spits out a good amount of errors when it finds files it doesn’t know how to deal with. For example:

```plaintext
"github.com/cespare/xxhash/v2" contains non-Go code that can't be inspected for further dependencies:
/go/pkg/mod/github.com/cespare/xxhash/v2@v2.2.0/xxhash_arm64.s
```

I also found there were a small set of licenses it didn’t find for the production files, but I’ll write about what I did to tackle that in the next section.

You can ignore packages using `--ignore github.com/cespare/xxhash/v2` , and it’s variadic, so you can pass more than one ignore to your command.

```bash
go-licenses report ./... --ignore pkg1 --ignore pkg2 \
  --template licenses.tpl > licenses.json
```

### How to find licenses it can't

There’s definitely more than one way to go on the hunt for licenses. I went with the simplistic approach of querying [pkg.go.dev](https://pkg.go.dev).

For all the licenses I checked on (~600 packages), it had them all! So it should be authoritative. Some caveats with this approach:

- Packages can have multiple licenses
- It relies on beautifulsoup and the format of the site, so this probably won’t work forever :)

To pull that information you need a package and a version, something you could get from running `go list -m all` or a more specific version that uses the JSON output (`go list -json all`) and looks at package types to see which ones are production only.

You could write a script to iterate and place the license information in a file you could use to power an SBOM or something like it.

```python
from typing import Optional

# pip install bs4 requests
import bs4
import requests
def get_license_from_go_pkg(package: str, version: str) -> Optional[str]:
    url = f"https://pkg.go.dev/{package}@{version}"
    resp = requests.get(url=url)
    resp.raise_for_status()
    soup = bs4.BeautifulSoup(resp.text, "html.parser")
    # this is probably the most brittle part, but I discovered it from
    # searching in the HTML. If this errors out it should just take a bit
    # of tweaking
    license_info = soup.find("a", {"data-test-id": "UnitHeader-license"})
    if license_info:
        return license_info.text
    return None
```

Calling this python snippet as

```bash
get_license_from_go_pkg("github.com/Knetic/govaluate","v3.0.1-0.20171022003610-9aa49832a739")
```

Will print out `MIT` .

### Wrapping up

`go-licenses` is a tool that should get you 90% of the way there, but using something like pkg.go.dev can help you with the rest. Hopefully these tools help you get all the license info you need to help your business.
